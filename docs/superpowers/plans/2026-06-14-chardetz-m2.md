**Goal:** First *working detection*. chardetz detects **UTF-8**, **Latin-1**, and **one single-byte charset** — each matching the uchardetz oracle exactly via the differential gate (now flipped to chardetz-vs-oracle). Ends with the first green prober → **public GitHub repo debut** (`pmarreck/chardetz`, name confirmed by Peter) → Garnix-green.

**Architecture:** Port uchardet's detection engine, scoped to 3 probers. `CodingStateMachine` drives the generated `SMModel`s (already in `src/tables/`); a `CharSetProber` interface unifies the probers; `UniversalDetector` is the dispatcher (BOM + uchardetz's BOM-less UTF-16 NUL heuristic + input classification + argmax-confidence winner). The detector core stays pure (no I/O); it exposes a Zig `detect(bytes) -> []const u8` mirroring uchardet's `handle_data`/`data_end`/`get_charset` semantics (the C FFI itself is M5).

**Tech stack:** Zig 0.16, the Phase-2 structs (`SMModel`/`PckInt`/`SequenceModel`) + Phase-3/4/5 generated tables, the Phase-8 in-harness uchardetz oracle, the corpus.

**Pinned oracle:** uchardetz @ `abacfc1fc86ef7618547d7dce7cc7501e756fa31` (unchanged).

**Key upstream facts (verified):**
- `nsSMState`: `eStart=0, eError=1, eItsMe=2`.
- `CodingStateMachine.NextState(c)`: `cls = classTable.get((u8)c)`; if state==eStart: `charLen = charLenTable[cls]`; `state = stateTable.get(state*classFactor + cls)`. (`PckInt.get` already implemented + tested in Phase 2.)
- `UTF8Prober`: count multibyte chars (charLen≥2 at eStart); `GetConfidence = (numMB<6) ? 1.0 - 0.99*(0.5^numMB) : 0.99`; HandleData shortcuts to eFoundIt when conf > `SHORTCUT_THRESHOLD=0.95` or state==eItsMe.
- Dispatcher `DataEnd` (eHighbyte): report argmax-confidence prober iff `maxConf > MINIMUM_THRESHOLD`; else report "" (negative). BOM/UTF-16 hits report immediately. Pure-ASCII path reports "ASCII".
- The uchardetz fork ADDED a BOM-less UTF-16 heuristic (≥20% NULs in one of even/odd byte positions, <5% in the other, ≥8 bytes → UTF-16BE/LE). Must be replicated faithfully (it's why `ja/utf-16be.txt` etc. detect).

The in-harness oracle test (Phase 8) currently asserts *uchardet vs corpus labels*. In M2 it FLIPS to **chardetz vs uchardet** (the real differential gate). But chardetz only implements a SUBSET of charsets in M2, so:

- Maintain an **`IMPLEMENTED_CHARSETS`** set in the test (M2: `{"UTF-8","ASCII","UTF-16","UTF-16BE","UTF-16LE","UTF-32","ISO-8859-1","WINDOWS-1252",<the one chosen SBCS charset(s)>}`).
- For each corpus file: run the oracle → `oracle_cs`. **If `oracle_cs` is in `IMPLEMENTED_CHARSETS`**, assert `chardetz.detect(bytes) == oracle_cs` (strict). **Else** skip and tally as "pending (prober lands in M3/M4)".
- Pending files are NOT divergences and NOT fenced — `expected_divergences.json` stays for genuine, documented chardetz≠oracle cases only (target: empty). Log the pending count so coverage growth is visible.
- This `IMPLEMENTED_CHARSETS` set is the milestone progress tracker; M3/M4 grow it until it's all charsets and every corpus file is asserted.

```zig
pub const CodingStateMachine = struct {
    model: *const state_machine.SMModel,
    current_state: SMState = .start,
    current_char_len: u32 = 0,
    pub fn init(m: *const state_machine.SMModel) CodingStateMachine { return .{ .model = m }; }
    pub fn nextState(self: *CodingStateMachine, c: u8) SMState {
        const cls = self.model.class_table.get(c);
        if (self.current_state == .start) self.current_char_len = self.model.char_len_table[cls];
        self.current_state = @enumFromInt(self.model.state_table.get(@intFromEnum(self.current_state) * self.model.class_factor + cls));
        return self.current_state;
    }
    pub fn getCurrentCharLen(self: CodingStateMachine) u32 { return self.current_char_len; }
    pub fn reset(self: *CodingStateMachine) void { self.current_state = .start; }
};
```
Re-export `coding_state_machine` + a `tables` convenience in `src/chardetz.zig` (tables already re-exported as `tables`). Add license header (ported logic).

## Risks
- **Float determinism** (the spec's flagged risk, now live): uchardet uses `float`; Zig `f32` with identical op order should match bit-for-bit. If a tie-break diverges, investigate (op ordering) before fencing; fence only a provably-arbitrary tie with documentation.
- **Latin1/SBCS class tables**: if `nsLatin1Prober`/`nsSBCharSetProber` rely on additional fixed tables beyond the generated ones, generate or hand-port them (licensed) — don't approximate.
- **Dispatcher scoping**: M2's 3-prober dispatcher must grow cleanly into the full group-prober structure (M3 `nsMBCSGroupProber`, M4 `nsSBCSGroupProber`) — keep the prober list extensible.
